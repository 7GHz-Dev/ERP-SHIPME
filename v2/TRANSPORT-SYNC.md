# ชีตงานขนส่ง → Supabase แบบอัตโนมัติ

หน้า **ปิดบัญชี** ดึงเลข BL / จำนวนตู้ จากชีตงานขนส่ง 2 ไฟล์

| ไฟล์ | ลิงก์ |
|---|---|
| สำเนาของ MAESOT FREEZONE 2026 | https://docs.google.com/spreadsheets/d/17NsBNqE8vlMfAH_CnUpms_jcrLQhs20Xw18yNHHTaT8/edit |
| สำเนาของ TRANSIT 2026 | https://docs.google.com/spreadsheets/d/1B733V3nfzECPxL0SHUG17Mo8Kzf0xnjirDK51Xe3Y-U/edit |

ระบบเดิมบน Apps Script อ่านชีตสดทุกครั้งที่เปิดหน้าปิดบัญชี แต่ v2 อ่านจาก Supabase
(Vercel เป็น serverless จะไปเปิดชีตทุกครั้งไม่ไหว — ช้าและชนโควตา Google)
ตัวเชื่อมนี้จึงกลับทาง: **ให้ชีตเป็นฝ่ายยิงข้อมูลเข้ามาเองทันทีที่มีคนแก้**

```
คนแก้เซลล์ในชีต
   └─ onEdit จดคิว → flushQueue (รายนาที) รอหยุดพิมพ์ 15 วิ → POST /api
        └─ v2 ลบข้อมูลของแท็บนั้นแล้วใส่ชุดใหม่ในทรานแซกชันเดียว
             └─ หน้าปิดบัญชีเห็นข้อมูลใหม่ทันที
```

## ทำไมต้อง "แทนที่ทั้งแท็บ" ไม่ใช่เติมทีละแถว

การแก้ในชีตมีทั้งแก้ค่าเดิม เพิ่มแถว และ **ลบแถว** ถ้าเติมอย่างเดียว
แถวที่ถูกลบไปแล้วจะค้างใน Supabase ตลอดไป แล้วหน้าปิดบัญชีจะนับตู้เกินจริง
จึงลบเฉพาะขอบเขต `source_file + source_sheet` นั้นแล้วใส่ชุดใหม่ **ในทรานแซกชันเดียว**
(ห้ามมีจังหวะที่ตารางว่าง ไม่งั้นคนที่เปิดหน้าปิดบัญชีพอดีจะไม่เห็นงานของตัวเอง)

## 1. ตั้ง TRANSPORT_SYNC_TOKEN

ค่านี้คือกุญแจที่ให้ชีตยิงเข้ามาได้ **เว้นว่าง = ปิดรับ sync ทั้งหมด**
เครื่องนี้สุ่มไว้ใน `v2/.env.local` แล้ว เอาค่าเดียวกันไปใส่ใน Vercel ด้วย:

```bash
grep TRANSPORT_SYNC_TOKEN v2/.env.local        # ดูค่า
vercel env add TRANSPORT_SYNC_TOKEN production # ตั้งบน Vercel (Sensitive)
```

## 2. ติดสคริปต์ในชีต (ทำทีละไฟล์ ทั้ง 2 ไฟล์)

1. เปิดชีต → **ส่วนขยาย → Apps Script**
2. ลบโค้ดเดิมในไฟล์ `Code.gs` ทิ้ง แล้ววางเนื้อหาจาก [`scripts/TransportSync.gs`](scripts/TransportSync.gs) ลงไป
3. แก้ `SYNC` 2 บรรทัดบนสุด:
   - `API_URL` = โดเมน Vercel ของคุณ ลงท้าย `/api`
   - `TOKEN` = ค่าเดียวกับข้อ 1
4. เลือกฟังก์ชัน **`setupSync`** แล้วกด **Run** ครั้งเดียว
   - ครั้งแรกจะขอสิทธิ์ → Review permissions → เลือกบัญชี → Advanced → Go to … → Allow
   - ต้องขอ 2 สิทธิ์: อ่านชีตนี้ กับ เชื่อมต่ออินเทอร์เน็ต (`UrlFetchApp`)
5. เสร็จแล้วจะเห็น toast "ติดตั้ง sync เรียบร้อย" และข้อมูลทั้งไฟล์ถูกยิงขึ้นไปครั้งแรกทันที

`setupSync` ติด trigger ให้ 4 ตัว:

| trigger | จับอะไร |
|---|---|
| `onSheetEdit` | คนพิมพ์แก้เซลล์ — จดคิวไว้เฉย ๆ |
| `onSheetChange` | เพิ่ม/ลบแถว เพิ่ม/ลบแท็บ (onEdit ไม่จับกรณีพวกนี้) |
| `flushQueue` รายนาที | **ตัวยิงจริง** — onEdit สร้าง trigger เองไม่ได้เพราะสิทธิ์จำกัด |
| `syncAllSheets` รายชั่วโมง | กันพลาด เช่นแก้จากมือถือบางรุ่น หรือตอนยิงไม่ออกเพราะเน็ตล่ม |

ข้อมูลจึงเข้าช้าสุด **~1 นาที** (Apps Script ตั้ง trigger ถี่กว่า 1 นาทีไม่ได้)

## 3. ตรวจว่าใช้ได้จริง

ในหน้า Apps Script เลือกฟังก์ชัน `testSync` แล้ว Run → ดู **Executions**
ต้องเห็นจำนวนแถวที่อ่านได้ และผลลัพธ์ `"ok":true`

ฝั่ง v2 เช็กได้จาก action `transportSyncStatus` (admin/manager เท่านั้น):

```bash
curl -s -X POST https://<โดเมน>/api -H 'content-type: text/plain' \
  -d '{"action":"transportSyncStatus","token":"<token ของผู้ดูแล>"}'
```

ตอบกลับเป็นรายแท็บพร้อม `lastSync` — **ถ้า `lastSync` ค้างอยู่ที่เดิมแปลว่า trigger ไม่ทำงานแล้ว**
(เช่นมีคนไปลบ trigger ทิ้ง หรือโดเมน Vercel เปลี่ยนแล้วไม่ได้แก้ `API_URL` ในชีต)

## คอลัมน์ที่ดึงเข้า Supabase

ตั้งแต่ 3 ก.ย. 2026 ดึง **ทุกคอลัมน์** ในชีต ไม่ใช่แค่ที่หน้าปิดบัญชีใช้

| ชีต | คอลัมน์ใน Supabase | ใช้ที่ไหน |
|---|---|---|
| TRANSPORT | `transport_date` | ค้นงานในหน้าปิดบัญชี |
| ชิปปิ้ง | `shipping` | จับคู่กับพนักงาน |
| เลข BL | `bl` | จัดกลุ่มงาน |
| CONTAINER NO. | `container_no` | นับจำนวนตู้ |
| ท่าส่งออก | `port` | |
| ชิปเปอร์ | `customer` | ชื่อลูกค้าในใบแจ้งหนี้ |
| VESSEL | `vessel` | |
| **แลก DO** | `do_fee` | **ใบแจ้งหนี้แบบ No VAT** |
| DEM | `dem` | |
| EXTRA MOVEMENT | `extra_movement` | |
| STORAGE | `storage` | |
| LIFT ON / OFF | `lift_on` / `lift_off` | |
| ORDER FORM | `order_form` | มีเฉพาะไฟล์ TRANSIT |
| ค่านายตรวจ | `inspector_fee` | |
| ค่าล่วงเวลา | `overtime` | |
| ค่าตะกั่ว | `seal_fee` | |
| คชจ. อื่นๆ | `other_fee` | |
| ค่า Detention | `detention` | |
| ค่าซ่อมตู้ | `repair_fee` | |
| หมายเหตุ | `note` | |
| รายชื่อคนรถ | `driver` | |
| ปิดบัญชีแล้ว | `settled` | มีเฉพาะไฟล์ TRANSIT |
| ส่งแม่สอด | `doc_sent_date` | ชื่อคอลัมน์ต่างกัน 2 ไฟล์ ความหมายเดียวกัน |
| เลขที่ใบแจ้งหนี้ | `invoice_no` | เลขที่ทีมบัญชีกรอกในชีตเอง (คนละชุดกับที่ v2 ออก) |

**สองไฟล์มีคอลัมน์ไม่เท่ากัน** — MAESOT ไม่มี `ORDER FORM` กับ `ปิดบัญชีแล้ว`
คอลัมน์ส่วนเสริมพวกนี้ไม่นับคะแนนตอนหาหัวตาราง ไฟล์ไหนไม่มีก็ได้ค่า default (0 / ว่าง)
ไม่ใช่ทำให้ทั้งแท็บถูกทิ้ง

**ตัวเลขที่เป็น `#REF!`** จากสูตรที่พังในชีตจะถูกเก็บเป็น **0** ทั้งฝั่งชีตและฝั่งรับ
ถ้าปล่อยผ่านจะกลายเป็น NaN แล้ว insert ลงคอลัมน์ตัวเลขไม่ผ่านทั้งก้อน

## เรื่องที่ต้องรู้

**ชื่อไฟล์ถูกยุบให้ตรงกับข้อมูลเดิม** — ชีตส่งชื่อจริงมาว่า `สำเนาของ TRANSIT 2026`
แต่ข้อมูลที่ import รอบแรกเก็บเป็น `TRANSIT` / `MAESOT FREEZONE`
`canonicalSourceFile()` ยุบให้ตรงกันก่อนบันทึก ไม่งั้น sync ครั้งแรกจะกลายเป็น
**เพิ่มข้อมูลซ้ำทั้งตาราง** แทนที่จะแทนที่ของเดิม
เพิ่มไฟล์ชีตใหม่ที่ไม่มีคำว่า MAESOT FREEZONE / TRANSIT อยู่ในชื่อ ให้ไปเพิ่มใน
`SOURCE_ORDER` ทั้งใน `src/lib/transport-sync.ts` และ `scripts/TransportSync.gs`

**หัวคอลัมน์หาเองอัตโนมัติ** — ไล่หาใน 15 แถวแรก รองรับชื่อไทย/อังกฤษหลายแบบ
(`TRANSPORT_ALIASES` ชุดเดียวกับ `Code.gs`) แท็บไหนหาหัวตารางไม่เจอจะถูกข้าม ไม่ใช่ล้มทั้งไฟล์

**แถวที่เว้นช่อง BL ไว้** — ในชีตจริง ตู้ใบที่ 2 ของ BL เดิมจะเว้นช่อง BL/ชิปเปอร์
สคริปต์จำบริบทแถวก่อนหน้ามาเติมให้ (ตรรกะเดียวกับ `scanTransport` ใน `Code.gs`)
แถวว่างทั้งแถว = จบกลุ่ม ไม่เติมข้ามไปกลุ่มถัดไป

**แถวที่ไม่มีวันที่ TRANSPORT จะถูกทิ้ง** — หน้าปิดบัญชีค้นด้วยวันที่ตรวจปล่อยเสมอ
แถวที่ไม่มีวันที่จึงไม่มีทางถูกค้นเจออยู่ดี

**ระบบเดิมยังอ่านชีตสดเหมือนเดิม** — ตัวเชื่อมนี้ไม่แตะ `Code.gs` ที่ root
เปิดใช้พร้อมกันได้ระหว่างที่ยังไม่ตัดระบบเก่า

**สิทธิ์** — สคริปต์รันด้วยบัญชีคนที่กด Run ครั้งแรก บัญชีนั้นต้องเปิดชีตได้
ถ้าคนนั้นถูกถอดสิทธิ์ออกจากชีตเมื่อไหร่ sync จะหยุดเงียบ ๆ ให้ดู `lastSync` ตามข้อ 3
