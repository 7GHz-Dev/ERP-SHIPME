# ส่งค่าใช้จ่ายพิเศษจาก ERP SHIPME เข้า ERP KOLA

เอกสารสำหรับผู้พัฒนา ERP SHIPME

เมื่อแผนกบัญชีของ SHIPME กดจัดชุดใบแจ้งหนี้ของ BL ใบใดใบหนึ่ง ให้ ERP SHIPME ส่งรายการค่าใช้จ่ายพิเศษพร้อมรูปแนบมาที่ ERP KOLA ตามสเปกนี้
ฝ่ายขายของ KOLA จะใช้ข้อมูลนี้เจรจา บันทึกยอดที่ตกลง และส่งให้หัวหน้าตรวจ

## Endpoint

```
POST https://erp-kola.vercel.app/api/shipme/special-charges
Content-Type: application/json
Authorization: Bearer <SHIPME_API_KEY>
```

KOLA จะให้ `SHIPME_API_KEY` แยกต่างหาก ห้ามใส่คีย์นี้ไว้ในโค้ดฝั่งเบราว์เซอร์

## Body

```json
{
  "batchId": "SHIPME-INV-2026-000123",
  "blNo": "AMP0561328B",
  "invoiceNo": "INV2026/0123",
  "issuedAt": "2026-11-09T10:30:00+07:00",
  "currency": "THB",
  "note": "ค่าใช้จ่ายเพิ่มจากตู้ล่าช้า",
  "items": [
    { "code": "DEM", "description": "ค่า DEM เกิน 3 วัน (2 ตู้)", "quantity": 2, "amount": 9000, "note": "ตู้ TCNU3365522, UETU8895265" },
    { "code": "LIFT", "description": "ค่ายกตู้เพิ่ม", "amount": 1500 }
  ],
  "attachments": [
    { "fileName": "receipt-dem.jpg", "contentType": "image/jpeg", "url": "https://files.shipme.example/abc.jpg" },
    { "fileName": "invoice.pdf", "contentType": "application/pdf", "dataBase64": "JVBERi0xLjQK..." }
  ]
}
```

| ช่อง | จำเป็น | คำอธิบาย |
|---|---|---|
| `batchId` | ✓ | เลขชุดใบแจ้งหนี้ที่ไม่ซ้ำกันใน SHIPME ถ้าส่งเลขเดิมซ้ำ ระบบจะอัปเดตชุดเดิมแทนการสร้างชุดใหม่ (ดูหัวข้อส่งซ้ำ) |
| `blNo` | ✓ | เลข BL ระบบไม่สนช่องว่างหรือตัวพิมพ์เล็กใหญ่ และใช้เลขนี้จับคู่กับงานใน ERP KOLA ให้เอง |
| `invoiceNo` | | เลขใบแจ้งหนี้ที่แสดงให้ฝ่ายขายเห็น |
| `issuedAt` | | วันเวลาที่ออกชุด รูปแบบ ISO 8601 |
| `currency` | | รหัสสกุลเงิน 3 ตัว ถ้าไม่ส่งจะใช้ `THB` |
| `note` | | หมายเหตุของทั้งชุด ไม่เกิน 2,000 ตัวอักษร |
| `items` | ✓ | รายการค่าใช้จ่าย 1–100 รายการ |
| `items[].description` | ✓ | ชื่อรายการ |
| `items[].amount` | ✓ | **ยอดรวมของรายการนั้น** (ไม่ใช่ราคาต่อหน่วย) เป็นตัวเลขไม่ติดลบ ทศนิยมได้ 2 ตำแหน่ง |
| `items[].quantity` | | ใช้แสดงผลเท่านั้น ระบบไม่เอาไปคูณ ถ้าไม่ส่งจะเป็น 1 |
| `items[].code` | | รหัสรายการของ SHIPME เช่น `DEM` |
| `items[].note` | | หมายเหตุของรายการ |
| `attachments` | | รูปหรือ PDF ไม่เกิน 10 ไฟล์ ไฟล์ละไม่เกิน 8 MB |
| `attachments[].fileName` | ✓ | ชื่อไฟล์ |
| `attachments[].contentType` | | `image/jpeg` · `image/png` · `image/webp` · `image/gif` · `image/heic` · `application/pdf` ถ้าไม่ส่ง ระบบจะเดาจากนามสกุลไฟล์ |
| `attachments[].url` | อย่างใดอย่างหนึ่ง | ลิงก์ `https://` ที่ ERP KOLA ดาวน์โหลดได้ภายใน 20 วินาที และควรใช้ได้อย่างน้อย 10 นาทีหลังส่ง |
| `attachments[].dataBase64` | อย่างใดอย่างหนึ่ง | ตัวไฟล์ในรูป base64 จะมี `data:...;base64,` นำหน้าหรือไม่ก็ได้ |

ทั้งคำขอ (รวมไฟล์ base64) ต้องไม่เกิน **4 MB** ถ้ารูปรวมกันใหญ่กว่านั้น ให้ส่งเป็น `url` แทน

## ผลตอบกลับ

| HTTP | ความหมาย | ตัวอย่าง body |
|---|---|---|
| `201` | สร้างชุดใหม่แล้ว | `{"ok":true,"id":"SPC-…","created":true,"jobMatched":true}` |
| `200` | อัปเดตชุดเดิมแล้ว (`batchId` เดิม และฝ่ายขายยังไม่ได้เริ่มเจรจา) | `{"ok":true,"id":"SPC-…","created":false,"jobMatched":true}` |
| `400` | ข้อมูลไม่ถูกต้อง ข้อความ error บอกชื่อช่องที่ผิด | `{"ok":false,"error":"items[0].amount: ต้องเป็นตัวเลขไม่ติดลบ"}` |
| `401` | API key ไม่ถูกต้อง | `{"ok":false,"error":"API key ไม่ถูกต้อง"}` |
| `409` | `batchId` นี้ฝ่ายขายเริ่มเจรจาไปแล้ว ระบบจึงไม่ทับ | `{"ok":false,"error":"…","id":"SPC-…","status":"NEGOTIATING"}` |
| `500` / `503` | ฝั่ง KOLA มีปัญหาหรือยังไม่พร้อม ส่งใหม่ภายหลังได้ | `{"ok":false,"error":"…"}` |

ถ้าระบบยังไม่พบงานที่ BL ตรงกัน คำขอจะยังได้ `201` และระบบเก็บชุดไว้ แต่ body จะมี `"jobMatched": false` และช่อง `warning` เพิ่มมา
ฝ่ายขายจะเห็นชุดนั้นพร้อมป้าย "ยังไม่พบงาน"

## ส่งซ้ำและการลองใหม่

- **ส่ง `batchId` เดิมซ้ำได้อย่างปลอดภัย** ระหว่างที่ชุดยังเป็น "ใหม่" ระบบจะแทนรายการและไฟล์ของ SHIPME ด้วยข้อมูลล่าสุด
  เมื่อได้ timeout หรือ `5xx` จึงส่งใหม่ด้วยข้อมูลเดิมได้เลย ไม่เกิดชุดซ้ำ
- **ถ้าฝ่ายขายเริ่มเจรจาแล้ว** ระบบจะตอบ `409` และไม่ทับข้อมูลที่ตกลงกันไว้ ถ้ามีรายการเปลี่ยน ให้ส่งเป็นชุดใหม่ด้วย `batchId` ใหม่
- **ระบบดาวน์โหลดไฟล์ทั้งหมดก่อนบันทึก** ถ้าไฟล์ใดดาวน์โหลดไม่ได้ ทั้งชุดจะไม่ถูกบันทึก (ได้ `500` พร้อมชื่อไฟล์) แก้ลิงก์แล้วส่งใหม่ได้ทันที

## ทดสอบด้วย curl

```bash
curl -X POST https://erp-kola.vercel.app/api/shipme/special-charges \
  -H "Authorization: Bearer $SHIPME_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"batchId":"TEST-0001","blNo":"AMP0561328B","items":[{"description":"ทดสอบ","amount":100}]}'
```

## สิ่งที่เกิดขึ้นฝั่ง KOLA หลังรับข้อมูล

ชุดขึ้นที่เมนู **ค่าใช้จ่ายพิเศษ SHIPME** ของ SALE OFFICER จากนั้นงานเดินดังนี้:

1. SALE OFFICER บันทึกยอดที่ตกลงต่อรายการ แนบหลักฐานการเจรจา แล้วส่งให้ SALE SUPERVISOR ตรวจ
2. SALE SUPERVISOR อนุมัติ หรือส่งกลับให้แก้

ทุกขั้นถูกบันทึกเป็นประวัติของชุดนั้น
ตอนนี้ยังไม่มีการส่งผลกลับไปที่ SHIPME ถ้าต้องการให้ส่งยอดที่อนุมัติกลับไป ให้แจ้ง KOLA เพื่อทำ endpoint หรือ webhook เพิ่ม
